# Foundation verification

Provision in the checkout with Node 26.10.0 and Python 3.13.17:

```sh
uv sync --locked --all-groups --python 3.13.17
npm ci --include=dev
uv run --locked --no-sync python scripts/provision_gitleaks.py
npm run verify
```

Use checkout-local `UV_CACHE_DIR=.cache/uv` and `npm_config_cache=.cache/npm` where a restricted host cannot access user caches. The project locks uv 0.13.5, Bandit 1.9.4, pip-audit 2.10.1, Playwright 1.64.1 and eslint-plugin-security 4.2.0. Gitleaks 8.30.1 is downloaded separately from its official release and its archive SHA-256 is verified before extracting only the executable. No global installation/configuration is required.

`npm run verify` runs Python branch coverage, JavaScript coverage, native Electron E2E, the integer coverage gate, TypeScript, ESLint, mypy, Ruff, formatting and security scans. It records every exit code in `coverage/verification.json` and fails if any command fails. `npm run verify:deterministic` executes the same deterministic checks without network advisory scans; CI provisions dependencies first, then runs deterministic execution and security scans in distinct steps. This is application-level isolation and request observation, not an OS-wide firewall claim. Unit doubles and the closed synthetic backend require no accounts, real model, editor, native SDK helper, microphone or screen access. Live tests stay explicitly skipped by default.

## Numeric coverage contract

`scripts/coverage-manifest.json` lists every maintained application Python and TypeScript/TSX module. It includes all provider/source/session policy, startup, domain, action, service, storage, framing, Electron launch/supervisor/account/main/IPC/security/preload, shared contracts/URL validation, renderer host and Markdown policy paths. All other renderer modules remain in ordinary coverage. Empty package initializers remain inventoried with zero executable statements. CSS/HTML/SQL are maintained non-executable assets validated through build, migrations and real-host behavior, and have no fabricated statement counts. Test fixtures and quality tooling are tested separately rather than counted as application runtime.

The checker requires a report entry for every inventoried module and fails on inventory drift, missing/empty/malformed reports, invalid integer counts, an entirely unexecuted trusted module, or insufficient coverage. It sums integer covered/total counts separately for statements and branches; it never trusts rounded display percentages. Each language must reach 80% statements / 75% branches over maintained source, and 90% / 85% over its explicitly enumerated trusted group. These are group thresholds, not a claim that every individual file meets them. Documented negative decision cases remain required regardless of percentages.

Python uses `pytest --cov=sage --cov-branch --cov-report=json` and includes unimported `sage` modules. Vitest's V8 include list seeds all maintained desktop source and emits `coverage/coverage-summary.json`. Main-entry unit tests exercise real registration/sender ownership/progress fencing/shutdown with Electron's native boundary doubled. The native host smoke and E2E remain separate real Electron evidence; their counters are not silently merged into unit coverage. No V8/Istanbul map merging or coverage collection bridge is used.

## Real-host E2E boundary

`npm run test:e2e` builds a separate `.cache/e2e` artifact and drives actual Electron, the maintained main entry/supervisor, actual sandboxed CJS preload, renderer, private framed pipes, Python startup, CoreService, ActionService and SQLite. Only this explicit build aliases `desktop/main/core-launch.ts` to a fixed committed fixture launcher. Production has no fake-provider environment/CLI/runtime selector or generic script override. The fixture uses the same Windows child-environment policy as the production launcher: blocked libuv-required lookup/profile/identity fields are explicitly empty, while reviewed OS roots and owned temp paths remain. The fixture replaces the startup module's provider constructor in its own Python process, supplies only closed synthetic scenarios, rejects sockets/process/helper launches, and records bounded event/attempt acknowledgements. It does not establish live Copilot SDK policy; the dedicated provider tests do.

Each launch uses an owned temporary root for userData, sessionData, temp, home and appData; the Python root is checked via actual database state. Tests retain that root only for their restart scenario, close Electron, wait for every recorded owned child PID to exit and then remove the root. No user notes/accounts/configuration are read. Outbound model requests are forbidden. Playwright's unfused automation artifact requires inspector/debug transport and is distinct from production fuses, CSP and package certification. Sandbox, context isolation, node-integration off, main sender validation and CSP stay enabled. The independent existing native smoke uses the production bundles without Playwright instrumentation.

`foundation.spec.ts` covers literal create/review/edit/review revision/save, zero writes before approval, exact persisted note and one operation, cancel, same-root restart/read, synthetic proposal/quota, cancellation-insensitive late completion, actual child crash/bounded restart/no replay and local-mode cloud rejection. SQLite connection instrumentation counts actual `INSERT INTO notes` attempts; negative flows require zero attempts as well as no notes/operations.

`recovery.spec.ts` uses an independent SQLite writer transaction for a real lock and test-only connection-level `SQLITE_FULL` injection at the actual note insertion. It verifies retained review and successful fresh-review retry. A test-only migration-read fault exercises actual startup failure, visible unavailable UI, unchanged schema/sentinel state, then successful app restart after removing the injected fault. These are controlled fault-injection tests, not OS disk exhaustion or an in-place startup repair feature. Neither test deletes/recreates the database.

`security.spec.ts` renders hostile Markdown through the actual Chromium SafeMarkdown path, checks ordinary formatting and absence of active HTML/media/unsafe URLs, observes browser request events and CSP violations before rendering, preserves and wraps the existing session deny callback, and counts actual arrivals at an owned loopback sink. Content causes zero remote attempts/arrivals and zero external-open calls. One explicit safe link causes exactly one validated host call, with only `shell.openExternal` stubbed in the test bootstrap. Invalid preload input and a separately forged main-frame identity both fail with zero effect attempts.

The positive renderer fetch is blocked before Playwright's request event; its CSP violation observes that attempt. A main-session fetch exercises the retained resource guard, and an independent runner fetch proves the sink can detect actual egress. This distinguishes CSP-blocked attempts, session request decisions and actual arrivals; it does not claim system-wide DNS/Internet capture. The Python fixture has its own socket/process guard. Sensitivity is demonstrated by temporary guard bypasses against loopback only, expecting the negative test to fail and restoring source in `finally`. The Python socket sensitivity establishes the test guard's effectiveness, not a production OS egress firewall. Production bundle/wheel tests reject test selectors, fixtures and collectors; Task 10 must inspect the final protected package inventory/fuses/signatures independently.

## Security reports and policy

`scripts/verify_security.py` exports all Python dependency groups with hashes from `uv.lock`, verifies the selected platform's package versions against the lock and installed environment, and runs strict hash-requiring pip-audit with resolution disabled. It audits the complete npm lock tree including development/optional/peer build dependencies. Missing JSON, tool/network failures, skipped/missing inventory and unknown Python advisory severity fail closed. No advisory is silently assigned a low severity.

Bandit scans all maintained Python under src/tests/scripts/e2e/desktop fixtures with `--ignore-nosec` and `--quiet`; informational progress is disabled so the JSON remains parseable above 50 files, while all metrics and lower findings remain. Its scanner-only home/cache roots are project-owned. ESLint's installed security rules scan all maintained JS/TS, including host/preload. Reports retain all lower static findings and security hotspots with their original rules/locations. Bandit High findings block. Lower Bandit severities and ESLint heuristic hotspots are visible review work under the approved no-untriaged-High/Critical threshold; a passing scan is not a zero-findings claim or an owner-accepted exception. A known reachable High/Critical cannot be waived by this script. Actual exceptions require finding-specific applicability, owner acceptance and expiry; none is supplied by default.

Gitleaks scans the current tree including untracked maintained source and tests, the validated committed base..head range, and the complete staged contents of every added/changed index file when present. Staged full-file scanning is stronger than added-lines-only scanning; deletions are not restored. Its explicit allowlist contains only dependency/build/generated/cache/report trees. Inline allow comments are disabled, an owned empty ignore directory prevents implicit `.gitleaksignore`/baseline suppression, and a runtime-constructed synthetic token proves detection plus redaction. No maintained test/source tree is excluded. Raw scanner output/diagnostics stay in memory; only allowlisted metadata is written to `coverage/security.json`. Values, matches, source snippets, author/email/message fields and raw errors are never persisted. Findings or incomplete scans return nonzero.

Gitleaks' default rule set differs from the earlier bounded literal-credential scanner. The existing Task 8 synthetic environment-secret test remains unchanged and its earlier bounded finding remains separately recorded; formal current-tree cleanliness does not erase that result. Generated Python bytecode is excluded explicitly, after the initial formal scan detected compiled synthetic fixtures. Known historical exposure in deleted original root `test.py` is reported separately and remains unresolved; no original literals/history are fetched or printed, and deletion/current-tree cleanliness does not prove revocation.

The PR workflow uses verified immutable official action commits, read-only contents permission, no persisted checkout credentials or repository secrets, and no publishing/dispatch. macOS/Windows artifacts include only explicit sanitized security/verification/coverage reports. Source workflow configuration is not Windows execution evidence. Native binary integrity/signatures/licenses and embedded binary vulnerabilities require the separate package inventory; pip/npm audits do not certify them.


## Native package checks

The application-directory core is built natively with CPython 3.13.17, PyInstaller 6.22.3 and hooks-contrib 2026.9. Use a separate project-owned build environment containing only runtime dependencies and the `build` group; a development environment can cause optional test/lint modules to enter PyInstaller analysis. The archive module allowlist fails on unexpected modules instead of silently shipping them.

Provisioning is an explicit network build step, never launch behavior. In a fresh checkout, `python scripts/provision_package.py` uses the pinned SDK's supported `python -m copilot download-runtime` route and checksum-pinned official gh ZIPs. It preserves the whole selected native platform tree and applicable notices, plus source inventory. Existing staging is never replaced implicitly. The selected resources are copied unchanged outside PyInstaller and ASAR. Upstream bundled plugins/assets are retained for byte integrity; empty-mode session policy disables ambient execution.

For example, POSIX shells can create the clean environment with:

```sh
UV_PROJECT_ENVIRONMENT="$PWD/.runtime/build-venv" uv sync --locked --no-dev --group build --python 3.13.17
.runtime/build-venv/bin/python scripts/build_core.py --output .runtime/package/core
.runtime/build-venv/bin/python -m scripts.stage_package
```

Keep UV runtime/bin/cache variables project-scoped as in the development setup; Windows uses `.runtime/build-venv/Scripts/python.exe` and its shell's environment-variable syntax. Native platform workflow source prepares these steps but is not completed platform evidence.

Build with `python scripts/build_core.py --output .runtime/package/core`, then `python -m scripts.stage_package` from the repository root with the clean build interpreter. Stage additionally needs the locked `node_modules` tree for host notices and npm's production dependency BOM. The output directory must be new. Run `npm run make` to create an OS-native portable ZIP on macOS or Windows; installers are deferred and no Squirrel lifecycle capability is provided. This has no updater or publish step, signing identity discovery, or notarization configuration. Windows must build and test on Windows. No registry, system PATH, loader state or global configuration workaround is introduced.

Run `node scripts/check_package.ts APP_PATH build/resource-manifest.json` against the actual app directory, then `node scripts/smoke_package.mjs RESOURCES_PATH`. The former inspects the actual ASAR for private test composition/credential patterns, reads production fuses, and compares every selected external file's path/type/size/SHA-256/mode/link against staging. It permits only the known host `app.asar`/`electron.icns` resources outside that baseline; ASAR content is inspected separately. The latter launches both fixed offline switches as separate direct children of the actual frozen core, validates one bounded metadata frame and one pinned SDK construction frame, and checks that neither changed its owned root. It then uses Node overlapped pipes and the same allowlisted environment, with no PATH/developer Python, to save a synthetic local note, restart, verify exact persistence and check truthful local-inference unavailability. The package workflow runs this gate on macOS and Windows; synthetic Node tests for framing and child cleanup run in normal verification. These checks make zero cloud/model calls and do not establish authenticated provider behavior, a real TLS handshake, main native UI, or clean-machine acceptance. Repeat package checks after ZIP extraction, and compare signatures/whole-container inventory separately.

The trusted core-only `--self-check` accepts no service options and emits exactly one bounded length-prefixed JSON frame then exits. It records runtime/SDK metadata and the same identity-context factory's offline TLS store/default-path/verification properties without storage, accounts, helpers, native runtime or network.
