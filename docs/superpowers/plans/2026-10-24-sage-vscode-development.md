# Sage VS Code Development Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create, review, test and open a four-file focus tracker from an empty local folder, then complete a reviewed follow-up without overwriting human edits.

**Architecture:** Keep job state, model policy and grants in the supervised Python core. An authenticated data bridge connects Electron main to one local VS Code extension; the extension alone owns local review gestures, file effects and the fixed test recipe. Source remains transient, effect receipts are durable, and interruption never replays work.

**Tech Stack:** Existing Python 3.13/Pydantic/SQLite, Electron/React/TypeScript, Node standard libraries, Vite/Vitest/Playwright; a bundled VS Code extension with development-only editor test/VSIX tooling. No workflow framework, product HTTP server or extension runtime dependency.

**Spec:** [Approved VS Code development specification](../specs/2026-10-23-sage-vscode-development-design.md), approved by the owner on 24 October 2026. Existing subagent-driven execution preference is preserved. **This plan awaits written-plan approval; no implementation is authorized by its existence.**

## Global Constraints

- Windows/macOS; one explicitly paired, trusted, local, single-folder VS Code window. Refuse remote/WSL/container/web/virtual/multi-root/Restricted Mode. Never install into, close, reload or change the SSH window or a shared user profile.
- Exactly `index.html`, `focus.js`, `focus.test.mjs`, `README.md`; ordinary top-level files. Creation requires a genuinely empty owner-controlled local folder, including hidden entries. Follow-up replaces exactly one existing manifest file.
- Tracker: named session, start/pause/reset, elapsed time, completed sessions and total during the current page session; disclose refresh reset. No dependencies, server or persistent history.
- Node `>=26.12.1 <27`, stable releases only. Initial standalone test-runtime validation target: exactly `26.12.1`; later eligible versions require recorded platform recipe evidence. Existing local `26.10.0` is below the floor. Do not upgrade global tools or use Electron's executable as standalone Node.
- Keep SDK `1.0.25`/runtime `1.0.102` and current locked foundation dependencies. Add only the exact editor development pins established in Task 3. No product model/API/library upgrade accompanies this slice.
- One active coding job; user text at most 32,000 Unicode code points; follow-up with 1–4 selected clean UTF-8/LF/no-BOM manifest documents, creation zero existing files; 32,000 per file and 64,000 total source/selected diagnostics/provider-visible metadata. Output: four creation files or one replacement, the same source limits, explanation at most 2,000 code points. Every serialized frame fits 1 MiB. Reject, never truncate or silently convert.
- No ambient source, hidden instructions, clipboard, terminal, credentials, environment, tabs, history, repository scan or diagnostics. The user previews selected disclosure and explicitly sends it. Pairing/readiness never calls a model.
- Cloud coding is unavailable in Local AI only before token/session access. Copilot coding returns validated data with empty mode, zero tools, denied permissions, disabled skills/hooks/MCP/subagents and owned disposable session state. Never read VS Code/Copilot private tokens or attach to another session.
- Raw TCP only on `127.0.0.1`, ephemeral port; ticket secret 256 bits, one-use/60-second expiry; mutual nonce proof; 10-second handshake; at most two unauthenticated sockets, one paired socket and eight pending authenticated frames per direction. No browser-facing execution API or automatic reconnect.
- Inference deadline 120 seconds; individual core RPC at most 30 seconds; review/grant five minutes; source/proposal/session UI text at most 30 minutes; source-free metadata/receipts 30 days. Cancellation/revision/disconnect/restart/clock rollback invalidate grants.
- Separate `code.create`, `code.replace`, `code.test`; exact binding and durable intent before effects. Exclusive `wx` creation is not a four-file transaction. No rollback/delete/retry, forced save, `saveAll`, automatic undo or stale overwrite.
- Test argv exactly `--test --test-isolation=none --test-reporter=tap focus.test.mjs`; absolute selected Node outside workspace, `shell:false`, `detached:false`, closed stdin. Thirty seconds, 256 KiB combined output, two seconds to force termination of the same live owned child and three more seconds to observe. No descendant containment claim or persisted-PID killing.
- Reuse `isolatedChildEnv` policy: empty PATH; owned TEMP/TMP/TMPDIR; Windows explicit blank identity/home slots and validated OS essentials. Preview the constructed map and validate actual native additions in real child fixtures. Test code still has the user's file/network/process authority.
- Deterministic tests use owned folders/profiles and no accounts/models. On macOS, refuse `CODEX_SANDBOX=seatbelt` before native GUI launch; use approved GUI-capable execution, preserving Chromium/editor sandbox and trust. No `--no-sandbox`, `--disable-gpu-sandbox`, `--disable-workspace-trust` or `ELECTRON_DISABLE_SANDBOX` workaround.
- Maintain 80/75 statement/branch coverage and 90/85 for trusted source; include every new runtime file in reviewed inventories. Preserve foundation note contracts, retention, provider tests, package fuses/CSP and current platform/live skips.
- No paid/live check, source push, merge, release, marketplace publication or binary upload is implied by plan approval. Prior one-shot live approvals are exhausted. Existing source-push/CI permission applies to the existing draft PR; review each exact diff and keep unreleased binary uploads disabled.
- Commands below use root cwd; run Python as `.venv/bin/uv run --locked --no-sync ...` (Windows equivalent under `.venv/Scripts`) and installed Node tools via `npx --no-install`. ## Review Focus

1. A Windows drive/case alias or changed folder after pairing must not select another destination; bind canonical URI and filesystem identity, revoke on workspace change. Tests: Tasks 3/4.
2. A fragmented or flooded authenticated stream must stay bounded and must not release source while authentication is incomplete. Tests: Task 3.
3. Astral Unicode, invalid UTF-8, BOM/CRLF and diagnostic text near a disclosure limit must produce the same decision in Python/TypeScript without conversion. Tests: Tasks 1/4.
4. A review window left open across source/grant expiry or revocation must not execute an old decision. Tests: Tasks 2/7/8.
5. A child that exits while a descendant holds stdout open must not hang verification or produce a false successful test receipt. Tests: Task 9.
